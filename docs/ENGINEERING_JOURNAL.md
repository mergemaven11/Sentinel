# Sentinel Engineering Journal

This journal is part of the project, not an afterthought.

The goal is to preserve the reasoning behind the work so that future me can remember what happened and so that interviewers can see how I troubleshoot and think through embedded problems.

## Session Template

### Date

YYYY-MM-DD

### Goal

What am I trying to build or understand today?

### Expected Behavior

What do I expect the hardware/software to do?

### What I Changed

Code, wiring, configuration, tools, or commands changed during this session.

### What Happened

What did I actually observe?

### Errors / Symptoms

Compiler errors, runtime behavior, incorrect sensor values, communication failures, visual issues, etc.

### Investigation

What did I inspect or measure?

Examples:

- Compiler output
- Serial logs
- Multimeter measurements
- Logic analyzer captures
- Datasheet/register documentation
- Wiring
- Task timing
- Memory usage

### Root Cause

What was actually wrong?

### Fix

What fixed the issue?

### What I Learned

Explain the lesson in my own words.

### New Terms

Record unfamiliar vocabulary and a short explanation.

### Next Step

What is the smallest useful thing to do next?
